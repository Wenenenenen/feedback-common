# 起音网格拟合台

现场录音的速度会变、切分音会盖过正拍，逐拍吸附容易把整段伴奏带偏。本工具在
5ms 帧（240 采样）粒度上对**全段**求最优节拍网格，而不是贪心逐拍跟踪。纯前端、
无节拍跟踪器、无第三方优化求解器，核心是手写的反向动态规划。

## 运行

直接用浏览器打开 `index.html` 即可（同目录的 `solver.js`、`wav.js`、`app.js`
需与页面放在一起）。页面顶部可载入文件，也可点「载入内置示例」使用 `guide.wav`
与 `guide.json`。

- 输入：48kHz / 16bit / 单声道 PCM WAV，最长 120 秒；起音候选 JSON
  （`beats`、`anchors`、`onsets`），最多 192 拍、24000 候选。
- 支持拖放 WAV 与 JSON 到页面。

## 模型与规则（与 `samples/onset-grid-cases.zip/约定.txt` 一致）

- 帧 = 240 采样（5ms）。拍长 P 取 48–234 帧之间 6 的倍数，内部以
  `p = P/6 ∈ [8,39]` 表示；相邻拍长差不超过 12 帧（`|Δp| ≤ 2`）。
- 反拍类型 `s=0` 在半拍 `P/2`，`s=1` 在三分之二拍 `2P/3`。
- 每个正/反拍位置在前后 3 帧窗内取 `max(0, 权重 − 2·距离)`，同分取较早候选；
  得分为 0 记未匹配（导出为 `null`）。
- 转移代价：`3·|Δp| + 7·[s 发生切换]`。锚点硬对齐，末锚点本身不计分。
- 全段总分最大；同分按每拍 `(P,s)` 的组合序列取字典序最小（P 升序优先，
  再按 s 升序）。
- 无可行解时单独标明，不沿用旧网格，导出按钮禁用。

## 算法（`solver.js`）

反向 DP。对每个拍号 b 维护该拍所有可达帧 u 与 64 种 `(p,s)` 组合的最优后缀值
`B_b(u,p,s)`（32 个拍长 × 2 种反拍类型）。帧由下一层可达帧反推，锚点拍只保留
锚点帧。末拍到达末锚点即终止、不计转移代价。重建时从拍号 0 起按 `(p,s)`
字典序贪心选取满足全局最优恒等式的组合，天然得到同分下的字典序最小解。

满额输入（192 拍 / 24000 候选 / 24000 帧）单次求解约 0.25–1.5 秒，满足 4 秒上限。

## 功能

- 改任意候选的正/反拍权重、增删候选，即时重解。
- 增删拍号锚点（表单或画布上 `Alt+点击`）；拍号 0 与末拍锚点必填、不可删。
- 撤销 / 重做（`Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z`），深拷贝历史栈。
- 画布叠加波形、起音候选柱、正/反拍线、锚点与播放头；点一拍查看匹配来源与小分。
- 试听原声 / 节拍 / 叠加三轨，可拖动进度。
- 导出网格 JSON（`{score, beats}`，字段 `frame,period,swing,onMatch,offMatch,
  onScore,offScore,penalty`，首拍 penalty 为 0）。
- 导出与原声等长的 48kHz/16bit/单声道节拍 WAV：正拍样本 12000、反拍 6000、
  其余 0，逐样本对齐。

## 测试

- `test-guide.js`：内置样例端到端求解。
- `test-rules.js`：匹配窗、衰减、同分较早候选、反拍位置、penalty 等规则。
- `test-lex.js`：同分字典序最小与未匹配 null。
- `fuzz-ref.py` + `run-case.js`：Python 暴力枚举参考实现与 JS DP 对拍
  （含无解案例），已跑 480+ 例零分歧。
- `perf.js`：满额性能。
- `e2e.js`：Playwright 驱动真实 Chromium 的页面端到端（载入、编辑、撤销重做、
  锚点增删、无解标记、两种导出、试听）。运行：
  `NODE_PATH=$(npm root -g) node e2e.js`
